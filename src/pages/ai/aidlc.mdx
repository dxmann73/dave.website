# (PDLC + SDLC) * AI => AIDLC

We are currently undergoing rapid changes in the realm of software engineering.
It feels a lot like the transition from [craft production](https://en.wikipedia.org/wiki/Craft_production)
to the [mechanized factory system](https://en.wikipedia.org/wiki/Factory_system) during industrialization.

This page aims to outline the changes I see and implement in my daily work.

## PDLC

Product development lifecycle, requirements engineering, prototyping.

POs and PMs have been blocked from lack of software engineers present; not anymore.
Need to be careful though, see
[engineering principles — hedging complexity](/ai/engineering#hedging-complexity).

## SDLC

Software development lifecycle.

Old way, slowly churning wheels, decoupled from one another as not to block:

New way, tight and fast loops with multitasking humans in it:

Loops are still there but different now for many reasons, mostly due to changed timing in certain areas.
- no need to do sprints anymore (link blog post)
- able to ship features on a daily basis => automate all the things or be bottlenecked
- triage incoming problems and solve them instantly/constantly
- chores and maintenancy easier and more frequent

The amount of stuff to ship increases, humans in the loop are gates as well as bottlenecks, need to support as well as possible.

=> Engineering first principles

### After-merge review

Release notes; new version
Kick off agents to enforce parallel architecture and adherence, i.e. Look at the while picture
E.g. one agent doing cyclomatic complexity, another one naming, one security, etc.
Do ALL user journeys

### Maintenance
