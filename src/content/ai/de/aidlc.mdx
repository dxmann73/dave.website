# (PDLC + SDLC) * AI => AIDLC

We are currently undergoing rapid changes in the realm of software engineering.
It feels a lot like the transition from [craft production](https://en.wikipedia.org/wiki/Craft_production)
to the [mechanized factory system](https://en.wikipedia.org/wiki/Factory_system) during industrialization.

This page aims to outline the changes I see and implement in my daily work.

## PDLC

PDLC = Product development lifecycle, requirements engineering, prototyping.

POs and PMs have been blocked from lack of software engineers present; not anymore.
Need to be careful though, see
[engineering principles — hedging complexity](/ai/engineering#hedging-complexity).

## SDLC

Software development lifecycle.

Old way, slowly churning wheels, decoupled from one another as not to block:

New way, tight and fast loops with multitasking humans in it:

Loops are still there but different now for many reasons, mostly due to changed timing in certain areas.
- no need to do sprints anymore (https://www.reddit.com/r/agile/comments/1s9vp1q/ai_agents_forced_us_to_completely_rethink_our/)
- able to ship features on a daily basis => automate all the things or be bottlenecked
- triage incoming problems and solve them instantly/constantly
- chores and maintenancy easier and more frequent

The amount of stuff to ship increases, humans in the loop are gates as well as bottlenecks, need to support as well as possible.

https://addyosmani.com/blog/orchestration-tax

=> Engineering first principles

## A*DLC

Agentic DLC or AI DLC, it makes sense to re-think our processes from the ground up.

### Work classification

Classify work into
Easy to parallelize, one shot probable => parallel agents
Weird behaviour, complicated feature / refactor => HITL

### Requirements and features

Product needs to talk to AI together with an engineer (can be back and forth)
The most important thing (context management) is to achieve ALIGNMENT
Theo: https://www.youtube.com/watch?v=xJaMTo2YgO8&t=1586s
Matt: /grill-me skill

You HAVE to read what the spec says. Do not gloss over the words and "just read the code"
Theo: https://www.youtube.com/watch?v=xJaMTo2YgO8&t=1440s
Matt Pocock disagrees TODO link

Make sure the initial artifacts are sound: Plans, AGENTS.md, Code, Tests...
Theo: https://www.youtube.com/watch?v=xJaMTo2YgO8&t=1791s

Result: A spec as a user journey, small slices work best
Check against current state, read SDDs and ADRs
Test cases should be in there
User journey will become part of the product description/specification

### Implementation

Create implementation plan
Use TDD approach (multiple sources)
  - reddit https://www.reddit.com/r/agile/comments/1s9vp1q/comment/odrbipe/
  - Matt
Verification through feedback loop
Make agents provide proof

### First review

Code review when work is done; use a fresh context
Usually agents forget a lot of things, so enforce basic compliance, build, tests, CI, e2e

### PR Prep

Check touched code for bugs => https://nolanlawson.com/2026/05/25/using-ai-to-write-better-code-more-slowly/?ck_subscriber_id=2755325874
TODO install skill and include in ADLC
Which features get touched / altered by this, check them
Thorough code review at end => HITL

### After-merge review

Release notes; new version
Kick off agents to enforce parallel architecture and adherence, i.e. Look at the while picture
E.g. one agent doing cyclomatic complexity, another one naming, one security, etc.
Cursor hardcore review skill? => https://www.youtube.com/watch?v=mh5XZ-L5SFQ

### Live prep and push

Do ALL user journeys
Watch this version in PROD, report and instantly analyze changed behaviours

### Maintenance

Check tooling and problems in dev setup
Do chores (MAINTENANCE.md)
Watch PROD as well as STAGE/TEST, create and triage bugs, try to fix them
Scan for security issues, look at incoming CVEs, triage them
