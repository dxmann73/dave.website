# i18n EN/DE Plan — English default, German translation

Date: 2026-06-14
Status: approved design, ready to implement

## Goal

Add full English + German support to the site using Astro native i18n. English is the
default (unprefixed); German lives under `/de`. Every page, UI string, and collection
entry must exist in both locales — enforced by tests. Initial content is duplicated
verbatim into both locales (the existing content is mixed DE/EN) and translated later,
tracked by a `needs_translation` flag.

Further languages are explicitly out of scope. The design should not actively block a
future third locale, but no work is done for it now.

## Decisions (locked)

| Topic | Decision |
| --- | --- |
| Default locale | `en`, unprefixed (`/about`, `/projects`, `/`) |
| German locale | `de`, prefixed (`/de/about`, `/de/projects`) |
| Astro config | `i18n: { defaultLocale: "en", locales: ["en","de"], routing: { prefixDefaultLocale: false } }` |
| Mechanism | Astro **native** i18n (replaces the homegrown projects-only routing) |
| Collections | per-locale folders `en/`, `de/` (extends current projects convention) |
| File routes | mirrored under `src/pages/de/`; home body extracted to a lang-aware component |
| UI strings | typed TS dict `src/i18n/ui.ts` (`as const`) + `useTranslations(lang)` helper, fail-fast on missing key |
| Switcher | header EN/DE toggle, maps current URL to its counterpart |
| Missing policy | **strict everywhere** — missing/empty translation fails the build/CI |
| Untranslated tracking | `needs_translation` flag + non-blocking report |
| SEO | dynamic `<html lang>`, hreflang alternates, sitemap i18n, per-locale RSS |
| Tests fast | `pnpm test` = generic registry deep-parity (replaces per-content tests) |
| Tests slow | `pnpm test:e2e` = build + crawl `dist/` (4 checks), zero new deps |

Note: `DEFAULT_LANG` in `src/lib/utils/projectsLang.ts` flips `"de"` → `"en"`. All
current German content becomes the *translation*; English originals start as duplicates.

## Surface inventory (what gets a second language)

| Surface | Current | Target |
| --- | --- | --- |
| Home `src/pages/index.astro` | DE, logic-heavy | extract body → `HomeBody.astro` (lang prop); `index.astro` (en) + `de/index.astro` thin wrappers |
| AI pages `src/pages/ai/*.mdx` (5) | DE/EN mixed MDX | duplicate to `src/pages/de/ai/*.mdx`; author independently per locale |
| `404.astro` | EN | add `src/pages/de/404.astro` |
| `pages` collection (about, contact) | DE | folders `en/`, `de/`; duplicate now |
| `projects` collection | `de/` only | add `en/` (duplicate); flip default to `en` |
| `posts` collection (9) | DE | folders `en/`, `de/`; duplicate now |
| `arbeitsweise.ts`, `motto.ts` | `de` key only | add `en` key (duplicate) |
| `config.json` profile | `bio`/`designation` DE | lang-key `bio` + `designation` (`name` stays shared) |
| `menu.json` | single labels | labels move into `ui.ts`; URLs resolved per-locale |
| Hardcoded chrome ("Projekte", "Referenzprojekte", "seit", titles) | DE strings in `.astro` | move into `ui.ts` |

## Implementation phases

### Phase 1 — i18n foundation
1. Add `i18n` block to `astro.config.mjs` (`defaultLocale: en`, `locales: [en, de]`,
   `prefixDefaultLocale: false`).
2. Create `src/i18n/ui.ts`: `as const` nested `{ en: {...}, de: {...} }` + typed
   `useTranslations(lang)` helper. Missing key → throw (fail-fast).
3. Create `src/i18n/utils.ts`: `getLangFromUrl`, `localizedPath`, counterpart-URL
   helper (wrap Astro `getRelativeLocaleUrl` / `getLocaleByPath`).
4. Refactor `src/lib/utils/projectsLang.ts`: `DEFAULT_LANG = "en"`; keep
   id→`{lang,slug}` parsing but align URL helpers with Astro i18n (or fold into
   `src/i18n/utils.ts`).
5. `Base.astro`: accept `lang` prop, set `<html lang={lang}>`, emit hreflang alternate
   `<link>` tags for the EN/DE pair.

### Phase 2 — content restructure (duplicate-now)
1. Move existing `posts/*` and `pages/*` into `de/` subfolders; copy to `en/` subfolders.
2. Add `projects/en/*` as copies of `projects/de/*`.
3. Update `content.config.ts` schemas: add optional `needs_translation: boolean` to
   posts/pages/projects. Glob patterns already recurse, so folders work as-is.
4. Update `getStaticPaths` in `[regular].astro`, `posts/*`, `projects/[...slug].astro`,
   `categories/*`, pagination to emit per-locale routes (locale-prefixed for `de`).
5. Flag duplicated `en/` entries still in German with `needs_translation: true`.

### Phase 3 — file routes + components
1. Extract home body → `src/layouts/components/HomeBody.astro` (lang prop; pulls
   lang-keyed profile/motto). `index.astro` and `de/index.astro` = thin wrappers.
2. Duplicate `ai/*.mdx` → `src/pages/de/ai/*.mdx`.
3. Add `src/pages/de/404.astro`.
4. Replace hardcoded chrome strings in `index.astro`, `projects/index.astro`,
   `Header.astro`, `Footer.astro` with `t()` lookups; menu labels from `ui.ts`,
   URLs per-locale.
5. Lang-key `config.profile.bio` + `designation`.

### Phase 4 — switcher + SEO
1. Header switcher component: EN/DE links to current page's counterpart URL
   (guaranteed to exist by strict policy).
2. `@astrojs/sitemap` i18n config (locales + defaultLocale) for hreflang pairing.
3. Per-locale RSS: create `src/pages/rss.xml.ts` (en) + `src/pages/de/rss.xml.ts`
   (none exist today).

### Phase 5 — tests
1. Delete `src/lib/data/arbeitsweise.test.ts` + `src/lib/data/motto.test.ts`.
2. `src/i18n/registry.ts`: array of all lang-keyed sources (ui dict, arbeitsweise,
   motto, profile) + optional per-source extra-invariant hook (preserve motto
   unique-id check).
3. `src/i18n/parity.test.ts` (fast): for each registry source assert same locale set,
   identical key shape across locales, all leaf strings non-empty; run extra-invariant
   hooks.
4. `tests/e2e/render.test.ts` (slow): `globalSetup` runs `pnpm build`; crawl
   `dist/**/*.html` with fs + regex (zero deps):
   - EN/DE route parity (every `/` route has a `/de` twin and vice versa)
   - non-empty main content (length threshold)
   - no leaked key tokens (raw `ui.` / `t(` / untranslated sentinel)
   - internal link integrity (every internal href → an emitted dist file)
5. Split scripts: `test` = fast parity only; `test:e2e` = build + crawl. CI runs both.
   Configure via two vitest projects or two config files.
6. `needs_translation` report: non-failing script/test that lists flagged collection
   entries + identical EN==DE UI pairs (the to-translate worklist).

### Phase 6 — docs reconciliation (existing notes)
1. `MAINTENANCE.md` already has a `## Content` section with the ongoing translation
   checks. Extend it (do not duplicate) with i18n-specific upkeep:
   - Review the `needs_translation` report worklist; clear flags as content is
     actually translated.
   - Run `pnpm test` (parity) + `pnpm test:e2e` (route/render) after content changes.
   - Watch for **drift**: EN and DE both present but edited out of sync. Tests cannot
     detect semantic drift — this stays a manual check (the existing
     "translation there but content seems different" note covers it).
2. `TODOs.md` — reconcile existing i18n items now subsumed by this plan:
   - "Add English translations under `src/content/projects/en/`" → covered by Phase 2.
   - "Add a language switcher on the projects list and detail pages" → covered by
     Phase 4 (site-wide switcher, supersedes projects-only).
   - "`en/` sibling for `projects.mdx`" → covered by per-locale folders.
   Remove or mark these done; keep unrelated TODOs (tag taxonomy, project images,
   testimonials, fill current project).

## Coverage gap (be explicit)
- Tests enforce: every page/key/entry **exists** and is **non-empty** in both locales,
  and flag **identical** (still-untranslated) pairs via `needs_translation`.
- Tests do **not** enforce: semantic equivalence / drift between an edited EN and a
  stale DE (or vice versa). That is unautomatable and remains a manual `MAINTENANCE.md`
  discipline.

## Risks
- Strict policy applies to the blog: every future post must ship EN+DE or the build
  fails. Accepted knowingly.
- Refactoring the working projects routing to Astro native i18n is the highest-risk
  step; do Phase 1+2 behind a branch and verify `pnpm build` + `pnpm check` before UI work.
